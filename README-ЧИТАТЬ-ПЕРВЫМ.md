## 2. Как загрузить

Судя по комментарию в вашем `index.html` («GitHub Pages cannot set HTTP headers»), сайт живёт на GitHub Pages. Инструкция под это. Если хостинг другой, скажите, перепишу.

### Через сайт GitHub, без командной строки

1. Откройте репозиторий сайта на github.com
2. **Сначала index.html.** Нажмите на файл `index.html` → карандаш (Edit) → выделите всё → вставьте содержимое нового `index.html` → Commit changes
3. **Потом папки.** Кнопка **Add file → Upload files**
4. Перетащите в окно браузера **папки целиком**: `img`, `events`, `lv`, `ru`. Не файлы по одному, а именно папки. GitHub сохранит вложенность сам
5. Внизу Commit changes
6. Подождите одну-две минуты, пока Pages пересоберётся. Статус видно во вкладке **Actions**

### Проверка после загрузки

Откройте по очереди:

- `maxbeitan.com` и найдите строку Aug 13 в календаре: там должна появиться ссылка **La Dolce Vita** и кнопка **Programme & tickets**
- `maxbeitan.com/events/2026-08-13-la-dolce-vita-riga/`
- `maxbeitan.com/lv/pasakumi/2026-08-13-la-dolce-vita-riga/`
- `maxbeitan.com/ru/sobytiya/2026-08-13-la-dolce-vita-riga/`

Если страница открылась, а фото нет, значит `img/la-dolce-vita-2026.jpg` не долетел. Проверьте, что он лежит в корневой папке `img`, рядом с `mb-monogram.svg`.

### Если что-то пойдёт не так

Ничего не удаляется. Все правки в `index.html` точечные, ваши стили и скрипты не тронуты. Откатиться можно кнопкой **History** на файле: GitHub хранит предыдущую версию.

## 3. Про Meta Pixel: `1414247989892701` это не он

`1414247989892701` это **ID рекламного аккаунта**. Пиксель это другой объект, и у него свой ID. Оба выглядят как 15-16 цифр, поэтому их постоянно путают.

Сейчас Meta называет пиксель **датасетом** (dataset). Это одно и то же: Dataset ID и Pixel ID это один номер под разными подписями.

### Как создать

1. Откройте **Events Manager**: business.facebook.com/events_manager
2. В левом меню **Connect Data Sources**
3. Выберите **Web**, нажмите **Connect**
4. Выберите **Meta Pixel**, снова **Connect**
5. Имя: `Max Beitan`
6. Адрес сайта: `https://maxbeitan.com` (можно пропустить)
7. **Continue**. На следующем экране появится **Dataset ID**. Это и есть то число, которое нужно вставить вместо `PIXEL_ID_HERE`

Вставить надо в **четыре** файла: `index.html` и все три страницы события. Ищите строку `fbq('init','PIXEL_ID_HERE');`

### Почему «add web» не срабатывает

По частоте, сверху вниз:

1. **Блокировщик рекламы.** Это причина номер один. uBlock, AdBlock, Ghostery, встроенная защита Brave и Safari режут запросы к `facebook.com` внутри самого Events Manager, и кнопки просто перестают работать без сообщения об ошибке. Откройте Events Manager в окне инкогнито с отключёнными расширениями или в другом браузере
2. **Аккаунт не в бизнес-портфеле.** Если рекламный аккаунт личный, а не внутри Business portfolio, Events Manager не даёт создавать источники данных. Проверьте в **Business Settings → Accounts → Ad Accounts**, что аккаунт `1414247989892701` привязан к портфелю
3. **Нет прав администратора** на портфеле. Роль Advertiser или Analyst создавать пиксели не может
4. **Всплывающие окна заблокированы.** Часть шагов открывается в новом окне

Если после инкогнито всё ещё висит, пришлите скриншот того экрана, где останавливается, разберём.

### Про согласие на cookies

Пиксель в файлах стоит в «тихом» режиме: он загружается, но события не шлёт, пока не будет согласия. Два варианта:

- **Есть баннер согласия** → из него вызовите `window.dispatchEvent(new Event('cookieConsentGranted'))`
- **Баннера нет** → вставьте перед блоком пикселя строку:
  `<script>window.hasCookieConsent = () => true;</script>`
  Формально в ЕС для рекламных трекеров баннер нужен. Решение ваше, я оставил и то и другое возможным.

## 4. Латышская и русская версии: да, нужны

Вы спросили, стоит ли. Стоит, и вот почему.

Концерт в Риге, площадка Русского театра, аудитория говорит на латышском и русском. Сайт был целиком на английском. То есть весь латышский и русский поиск проходил мимо: не «работал хуже», а проходил мимо.

Обе версии уже в архиве. Между ними прописан `hreflang`, так что Google понимает, что это одна страница на трёх языках, и показывает нужную версию нужному человеку. Внизу каждой страницы переключатель языков.

**Одна оговорка.** Три языковые версии есть только у страницы события. Главная осталась английской. Это нормально: главная это ваша международная витрина, а продаёт билеты именно страница события. К декабрьскому гала имеет смысл сделать латышскую версию биографии, но это не задача этих десяти дней.

| Что | Было | Стало |

| Инструмент | «Страдивари Archinto 1689» | «Итальянская виолончель из частной коллекции» |

| Языки | Только английский | EN + LV + RU, с hreflang и переключателем |
| Афиши | 1080x1080, без логотипов | 1080x1350 (формат 4:5) и 1080x1920, с полосой логотипов BMF, Čehova teātris, Biļešu Serviss |

Строчку про Страдивари я оставил **только в биографии**, где сказано «играл на инструментах Антонио Страдивари и Давида Теклера». Это ваш собственный текст с сайта, он про прошлое, а не про 13 августа, и вопросов не вызовет.
